# E-03: protokol pra-registrasi (prompt paraphrase vs plain)

Ditetapkan 17 Oktober 2026, sebelum data E-03 ada. Aturan yang sama tertulis di SDD 9.5.
Penyimpangan dari protokol ini wajib diungkap di Bab 3.

## Tujuan

Membandingkan `rag.prompt_variant` = `paraphrase` dan `plain` pada dua hal: kesetiaan jawaban
(halusinasi) dan tingkat menyalin dari sumber.

## Data

- Set uji resmi (`split` = `test`, MS5), dengan model utama sesuai keputusan saat itu (E-04).
- Set dev hanya dipakai untuk menguji alat, tidak untuk keputusan.

## Pasangan

Hanya pertanyaan yang dijawab (status bukan penolakan) oleh kedua varian yang dibandingkan.
Jumlah pertanyaan yang dikeluarkan dilaporkan per varian.

## Metrik

- Halusinasi: anotasi manusia. Definisi: setiap klaim harus didukung potongan yang dikutip
  (citations) jawaban itu.
- Utama: coverage dan density extractive fragments Grusky dkk. 2018, tanpa perubahan.
- Pendamping: coverage dan density tanpa entitas. Token jawaban dari span email, URL (diawali
  `http://`, `https://`, atau `www.`), atau kata (dipisah spasi) yang memuat digit tidak boleh
  masuk fragmen, dan penyebutnya |S| − |E|. Jawaban yang seluruhnya entitas bernilai kosong,
  dikeluarkan dari rata-rata, dan jumlahnya dilaporkan.
- Kedua metrik salin dihitung terhadap dua sumber: potongan yang dikutip, dan semua potongan
  konteks yang dikirim ke LLM.

## Aturan keputusan

1. Varian dengan jumlah jawaban berhalusinasi lebih sedikit menang.
2. Bila seri, varian dengan rata-rata density kutip (Grusky asli) lebih rendah menang.
3. Bila masih seri, `paraphrase` (bawaan saat ini) menang.

Coverage dan metrik tanpa entitas dilaporkan, tetapi tidak menentukan keputusan.

## Alasan urutan

- Ladhak dkk. 2022: jawaban yang jarang menyalin hanya bernilai bila tetap setia. Karena itu
  kesetiaan (halusinasi) didahulukan, dan tingkat salin hanya pemecah seri.
- Grusky dkk. 2018: definisi coverage dan density yang dipakai sebagai metrik utama.

## Keterbatasan

- Nama orang, prodi, dan istilah tidak di-mask, karena butuh model NER yang tidak objektif
  untuk tujuan ini. Fragmen berisi nama tetap ikut dihitung di metrik tanpa entitas.
- Set uji kecil (n kecil): selisih kecil dibaca sebagai indikasi, bukan bukti.
- Aturan ini ditetapkan 17 Oktober 2026 sebelum data E-03. Penyimpangan apa pun wajib diungkap
  di Bab 3.

## Cara menjalankan

Varian prompt dipilih lewat config (`rag.prompt_variant`), bukan flag CLI. Siapkan dua file
config yang hanya berbeda di kunci itu, misalnya `config/e03-paraphrase.yaml` dan
`config/e03-plain.yaml`.

```
python -m mica.eval generation --config config/e03-paraphrase.yaml \
    --dataset data/eval/questions.jsonl --out results/E-03 --experiment E-03
python -m mica.eval generation --config config/e03-plain.yaml \
    --dataset data/eval/questions.jsonl --out results/E-03 --experiment E-03
python -m mica.eval copy --config config/e03-paraphrase.yaml \
    --runs results/E-03/<run paraphrase> results/E-03/<run plain> --out results/E-03
```

Kedua perintah `generation` memanggil Groq (memakai kuota) dan belum dijalankan.
`eval generation` saat ini hanya menjalankan split `dev`; dukungan split `test` (dengan kunci
`data/eval/LOCK`) perlu ditambahkan sebelum MS5. `eval copy` tidak memanggil LLM.
