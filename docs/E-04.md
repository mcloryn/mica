# E-04: pembanding kualitas Gemini (pra-registrasi)

Ditetapkan 19 Oktober 2026, sebelum run Gemini mana pun pada pertanyaan dev atau uji. Aturan di
bawah tidak diubah setelah data ada; penyimpangan wajib ditulis di hasil dan diungkap di Bab 3.

## Tujuan

- Mengukur selisih kualitas jawaban Groq `openai/gpt-oss-120b` dan `openai/gpt-oss-20b`
  terhadap Gemini, pada pertanyaan, KB, retrieval, dan prompt yang sama.
- Gemini hanya pembanding kualitas. Gemini gugur untuk kiosk karena kendala keras (syarat tier
  gratis; SDD 8.2, N-09), sehingga hasil E-04 **tidak mengubah model kiosk** (`llm.chain`
  kiosk tetap Groq). Hasilnya dipakai untuk menjelaskan berapa kualitas yang dilepas karena
  kendala itu.
- Gemini hanya boleh dipakai saat `app.mode: dev` (`GeminiProvider` dan `--model gemini:...`
  ditolak di kiosk).

## Model Gemini

- Terpilih: **`gemini:gemini-3.8-flash`** (`modelVersion` di respons: `gemini-3.8-flash`).
  Dicek 19 Okt 2026, 04:23 UTC (11:23 WIB) lewat `GET v1beta/models` dengan key dev.
- Aturan pemilihan:
  1. Hanya model stabil: nama tanpa `preview`, `experimental`/`exp`, atau alias `latest`.
  2. Mendukung `generateContent` (`supportedGenerationMethods`) dan keluaran JSON terstruktur
     (`responseMimeType: application/json` + `responseSchema`), dibuktikan dengan satu
     permintaan uji kecil berteks dummy yang lolos `parse_output`.
  3. Hanya model teks umum (bukan varian image, TTS, transcribe, omni, robotics, Gemma).
  4. Urutan kelas: pro > flash > flash-lite; dalam satu kelas dipilih versi terbaru.
  5. Bila permintaan uji ditolak (429/403, atau model tidak tersedia untuk key ini), turun ke
     model berikutnya.
- Jejak pemilihan:
  - Kelas pro: satu-satunya model pro stabil, `gemini-2.5-pro`, menjawab **404**
    ("no longer available to new users"). `gemini-3.1-pro-preview` dan `gemini-pro-latest`
    gugur karena aturan 1. Kelas pro kosong.
  - Kelas flash: model stabil `gemini-2.5-flash`, `gemini-3.5-flash`, `gemini-3.6-flash`,
    `gemini-3.7-flash`, `gemini-3.8-flash`. Yang terbaru, `gemini-3.8-flash`, lolos uji (200,
    JSON valid sesuai skema). `gemini-3-flash-preview`, `gemini-flash-latest`, dan
    `gemini-omni-*` gugur.
  - `gemini-4-argon` tidak masuk kelas pro, flash, maupun flash-lite, sehingga tidak termasuk.
- Kuota yang terlihat: respons tidak memuat header kuota atau rate limit, dan tidak ada 429 pada
  5 permintaan uji. Batas tier gratis tidak bisa dibaca dari API. Setiap 429 dan waktu tunggu
  dicatat di run.json (`llm_calls.retries_429`, `wait_429_s`).
- Latensi permintaan uji (prompt sekitar 50 token): 3,2 sampai 10,2 detik.
- Bukti: `results/E-04/gemini-model-selection-20261019.json` (daftar model dan hasil uji, tanpa key).

## Kondisi (sama dengan run 120b dev)

Acuan: `results/E-02/20261017-122758-E-02-dev-hybrid-gpt-oss-120b-gateoff/run.json`.

| Field | Nilai acuan | Gemini |
| --- | --- | --- |
| KB | `dev-2026-10-15-v2` | sama |
| Dataset | `data/eval/questions.jsonl`, sha256 `9dc9c399…69627a`, split dev (45) | sama |
| Embedder | `BAAI/bge-m3` @ `9a0624b8…` | sama |
| Retrieval | hybrid, top_k 5, rrf_k 60, kandidat 20, reranker mati | sama |
| Gerbang | mati (`--gate-off`, threshold efektif null) | sama |
| Cek angka | menyala; status cek mati dihitung offline | sama |
| Follow-up | concat, history_turns 1 | sama |
| Prompt | variant paraphrase, `PROMPT_VERSION` v2 | sama |
| Skema keluaran | SDD 5.3 (status, answer, citations; citations dibatasi ke id potongan) | sama isinya, format `responseSchema` Gemini (subset OpenAPI, tanpa `additionalProperties`); validasi keluaran tetap `parse_output` yang sama |
| temperature | 0,2 | sama |
| Rantai | hanya model pertama (`--model`), tanpa cadangan | hanya `gemini:gemini-3.8-flash`, tanpa jatuh ke Groq; dicatat di `run.json` `llm.chain_effective` |
| Cache | `data/cache/llm/`, kunci = hash badan request | sama |
| scrub_pii | aktif | aktif |
| Pembatas laju | 6.000 token per menit | sama |

Field yang tidak bisa disamakan:

- `reasoning_effort: low`: parameter khusus gpt-oss di Groq. Untuk Gemini dipetakan ke
  `generationConfig.thinkingConfig.thinkingLevel: low` (keputusan pengguna 19 Okt 2026).
  Besarnya penalaran tidak setara antarpenyedia.
- `timeout_s`: acuan 10 detik. Untuk Gemini dipakai **60 detik** (`--timeout-s 60`, keputusan
  pengguna 19 Okt 2026). Alasannya, permintaan uji kecil saja butuh 3 sampai 10 detik, dan
  yang diukur di sini kualitas, bukan latensi. run.json mencatat `timeout_s`,
  `timeout_s_config`, dan `timeout_source`.
- Token: `completion_tokens` Gemini = `candidatesTokenCount` (tanpa token berpikir), sedangkan
  `total_tokens` = `totalTokenCount` (termasuk token berpikir). Token tidak dibandingkan lintas
  penyedia.
- Cache: kunci cache Gemini memuat `thinkingConfig`, jadi tidak ada cache bersama dengan
  Groq.

Perintah run dev:

```
python -m mica.eval generation --config config/dev.yaml --dataset data/eval/questions.jsonl \
    --out results/E-04 --gate-off --experiment E-04 --model gemini:gemini-3.8-flash --timeout-s 60
```

Bila 429: tunggu sesuai `EvalLlm` (retry-after atau 10 detik, maksimal 5 kali), lalu lanjut.
Bila kuota harian habis, jawaban yang sudah ada tersimpan di cache. Run diulang dengan perintah
yang sama setelah kuota pulih, dan pertanyaan yang sudah ada diambil dari cache.

## Bagian DEV: uji coba

- Set dev lama (d001-d045), 120b dan 20b dari run E-02/E-04 dev yang sudah ada; Gemini dari run
  baru di atas.
- Metrik otomatis (`scripts/compare_models.py`, ambang null, cek angka menyala): salah tolak
  (answerable + followup tidak dijawab), tolak benar (out_of_kb ditolak; jauh/dekat), premis
  salah (terbaik/aman/gagal), status per pertanyaan, gagal skema, unavailable (termasuk 429 yang
  gagal setelah coba ulang), dan jumlah coba ulang 429.
- Latensi LLM p50/p95 hanya dicatat dan tidak dibandingkan. Penyedia, jaringan, dan timeout
  berbeda.
- Lembar anotasi `annotate_generation.csv` run Gemini diisi dengan saran Claude, lalu diperiksa
  penilai. Hasilnya dilaporkan sebagai **uji coba** ("anotasi Claude yang diperiksa"), bukan
  anotasi manusia independen, sama dengan 120b/20b dev (lihat ANNOTATION.md di folder run).
- Hasil dev tidak dipakai untuk kesimpulan utama.

## Bagian SET UJI: analisis utama

- Ketiga model (`groq:openai/gpt-oss-120b`, `groq:openai/gpt-oss-20b`,
  `gemini:gemini-3.8-flash`) dijalankan di set uji resmi (`--split test`, LOCK cocok, KB
  `official`; docs/DATASET.md) dengan kondisi tabel di atas.
- Anotasi buta:
  - nama model disembunyikan;
  - baris dari ketiga model digabung dalam satu lembar, dan urutannya diacak dengan
    `random.Random(20261018)`. Seed dibaca dari docs/DATASET.md (seed pembagian), bukan dari
    argumen;
  - kunci (baris -> model) disimpan terpisah dan tidak dibuka sampai anotasi selesai;
  - tanpa saran Claude;
  - idealnya 2 penilai independen, dengan Cohen's kappa per kolom (benar, halusinasi).
    Ketidaksepakatan diputuskan lewat diskusi setelah kappa dihitung.
- Metrik per model:
  - tingkat halusinasi = jawaban berlabel halusinasi / jawaban yang dianotasi (status answered
    atau false_premise, cek angka mati), dengan CI 95% Wilson;
  - jawaban benar = jawaban berlabel benar / jawaban yang dianotasi, dengan CI 95% Wilson;
  - metrik otomatis bagian DEV.
- Uji berpasangan 120b vs Gemini: McNemar eksak (binomial dua sisi atas pasangan sumbang)
  untuk halusinasi dan untuk jawaban benar, pada pertanyaan yang jawabannya dianotasi untuk
  kedua model. Jumlah pasangan dan pasangan sumbang dilaporkan. 20b vs Gemini dilaporkan
  sebagai deskriptif.
- **Run set uji Gemini MENUNGGU persetujuan pembimbing**, karena potongan dokumen resmi akan
  terkirim ke Gemini tier gratis. Run 120b dan 20b di set uji tidak menunggu persetujuan ini.
  Bila persetujuan tidak diberikan, bagian SET UJI hanya membandingkan 120b dan 20b, dan Gemini
  dilaporkan dari bagian DEV saja dengan label uji coba.
