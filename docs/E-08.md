# E-08: penamaan warna pakaian atas (pra-registrasi)

Ditetapkan 18 Oktober 2026, sebelum label warna dikumpulkan. Aturan di bawah tidak diubah
setelah data ada; penyimpangan wajib ditulis di hasil dan diungkap di Bab 3. Angka yang belum
disepakati ditulis TBD.

Kunci yang diputuskan: `vision.region`, `vision.color.method`, `vision.color.min_majority`
(SDD 9.5, bagian 12).

## Data

- Frame = frame E-07 bagian (a), `data/eval/vision/<nama>/` (gambar, label YOLO, manifest).
  Aturan privasi, persetujuan, dan penghapusan sama dengan docs/E-07.md.
- `colors.csv` (penilai 1) dan `colors_rater2.csv` (penilai 2), di folder dataset, kolom:

| Kolom | Isi |
| --- | --- |
| `frame` | `id` frame di manifest |
| `track` | Indeks baris orang di file label YOLO frame itu, mulai dari 0 |
| `color_label` | Warna baju atas, salah satu dari 11 label di bawah |

- Daftar label = 11 nama warna dasar tabel van de Weijer dalam Bahasa Indonesia, sama dengan
  `COLOR_NAMES` di `mica/vision/color.py`: hitam, biru, cokelat, abu-abu, hijau, oranye,
  merah muda, ungu, merah, putih, kuning. Label lain ditolak.
- Kedua penilai memberi label secara independen (tidak melihat label penilai lain maupun
  keluaran MICA). Cohen's kappa dihitung atas pasangan (frame, track) yang ada di kedua file.
  Pasangan yang tidak disepakati dikeluarkan dari perhitungan akurasi; jumlahnya dilaporkan.
  Pasangan yang hanya ada di satu file juga dikeluarkan dan dilaporkan.

## Kandidat

- Region {`keypoint_torso`, `box_upper`} x metode {`ColorNamesLut`, `HsvRuleNamer`} = 4
  kombinasi.
- Parameter area pada nilai coba sekarang (SDD bagian 12): `box_upper` top/bottom/side =
  0,35/0,65/0,25; `keypoint_torso` min_kp_conf/shrink/torso_aspect = 0,5/0,15/1,2 (dengan
  cadangan `box_upper`).
- Orang di frame diambil dari deteksi `yolo26n-pose` (conf = `vision.conf`): setiap kotak label
  dipasangkan ke deteksi dengan IoU tertinggi (≥ 0,5, satu deteksi per kotak). Kotak dan keypoint
  deteksi itu dipakai oleh kedua region, sama seperti di kiosk. Kotak label tanpa pasangan
  dikeluarkan dan jumlahnya dilaporkan.
- `HsvRuleNamer` (baseline) belum dibuat saat dokumen ini ditetapkan; aturannya harus
  di-commit sebelum label warna dibuka. Sampai itu, perintah menandai kombinasinya "tidak
  tersedia" dan verdict tidak memilih pemenang.

## Metrik

- Prediksi tahap 1 = warna suara terbanyak (`ColorResult.top`), tanpa `min_majority`. Area
  tanpa piksel = tanpa prediksi (salah).
- Akurasi, akurasi per warna (recall per label benar), macro-F1, dan confusion matrix (baris =
  label benar, kolom = prediksi). Macro-F1 = rata-rata F1 per label atas gabungan label benar
  dan label prediksi (F1 = 0 bila presisi dan recall 0).

## Aturan pemilihan (mekanis, `verdict.md`)

1. Pilih kombinasi region x metode dengan macro-F1 tertinggi (`min_majority` tidak dipakai di
   tahap ini). Seri -> akurasi lebih tinggi, lalu pilihan ADR saat ini (`keypoint_torso`,
   `color_names_lut`).
2. Pada kombinasi pemenang, `min_majority` ∈ {0,5, 0,6, 0,7}: warna disebut bila proporsi suara
   terbanyak ≥ `min_majority`, selain itu sapaan umum. Pilih nilai dengan presisi tertinggi
   (benar / disebut warna). Seri -> nilai lebih kecil (lebih banyak sapaan berwarna). Nilai yang
   tidak pernah menyebut warna tidak bisa dipilih. Alasan: menyebut warna yang salah lebih buruk
   daripada sapaan umum (tujuan "tidak sok tau").
3. Cakupan (persen sapaan berwarna = disebut / semua) selalu dilaporkan.

## Perintah

Hanya jalan di mode dev.

```
python -m mica.eval color --config config/dev.yaml --dataset data/eval/vision/<nama> \
    --labels colors.csv --labels2 colors_rater2.csv --out results/E-08/
```

Hasil: `agreement.json` (kappa, jumlah sepakat dan tidak), `summary.csv`, `per_color.csv`,
`confusion_<region>_<metode>.csv`, `min_majority.csv`, `per_item.csv`, `verdict.md`, dan
`run.json`.

## Keterbatasan

- Persepsi warna subjektif; karena itu dua penilai dan kappa dilaporkan.
