## Data

### (a) Frame berlabel untuk deteksi

`data/eval/vision/<nama>/`:

- `images/`: frame JPG/PNG dari kamera kiosk (atau kamera yang sama jenisnya).
- `labels/`: satu file teks per gambar, nama sama dengan gambar (`images/f001.jpg` ->
  `labels/f001.txt`), format YOLO: satu baris per orang `0 cx cy w h` (kelas 0 = person,
  koordinat dinormalisasi 0 sampai 1). File kosong = frame tanpa orang (sah, menguji deteksi
  palsu). File yang tidak ada atau kelas selain 0 ditolak.
- `manifest.jsonl`, satu objek JSON per frame:

| Field | Wajib | Isi |
| --- | --- | --- |
| `id` | ya | ID unik frame, mis. `r01-f001` |
| `file` | ya | Path gambar relatif terhadap folder manifest, mis. `images/r01-f001.jpg` |
| `relawan` | ya | Kode anonim relawan di frame (mis. `R01`; beberapa dipisah koma; `-` bila kosong) |
| `persetujuan` | ya | Harus `true` untuk semua relawan di frame |
| `cahaya` | ya | Kondisi cahaya, mis. `terang`, `redup`, `lampu-belakang` |
| `jarak` | ya | Jarak kasar ke kamera, mis. `dekat`, `sedang`, `jauh` |

Urutan baris di dalam file label penting: E-08 menunjuk orang dengan indeks baris (0, 1, ...).

### (b) Klip skenario kunjungan

`data/eval/vision_scenarios/<nama>/`:

- klip video (mis. MP4) dari kamera kiosk, laju frame tetap;
- `manifest.jsonl`: `id`, `file` (relatif terhadap folder), `persetujuan` (harus `true`);
- `annotations.jsonl`: anotasi waktu manusia, satu baris per kemunculan orang:

| Field | Wajib | Isi |
| --- | --- | --- |
| `clip` | ya | `id` klip di manifest |
| `orang` | ya | Kode anonim orang di klip (mis. `R01`) |
| `jenis` | ya | `lewat` (tidak berhenti) atau `berhenti` |
| `masuk` | ya | Detik klip saat orang mulai terlihat di depan kiosk |
| `berhenti` | untuk `berhenti` | Detik klip saat orang mulai berhenti di depan kiosk |
| `pergi` | ya | Detik klip saat orang pergi (keluar dari depan kiosk) |

"Kembali" ditulis sebagai baris `berhenti` baru dengan `orang` yang sama. Waktu dibaca dari
pemutar video (frame / fps), dengan ketelitian 0,1 detik.

### Formulir persetujuan relawan (wajah dan tubuh)

Setiap relawan menandatangani persetujuan tertulis sebelum direkam. Isinya:

1. Tujuan: wajah dan tubuh relawan direkam (foto dan video) untuk mengukur ketepatan deteksi
   orang, sapaan, dan penamaan warna baju MICA (kiosk informasi PMB Universitas Mikroskil)
   dalam skripsi S-1; tidak dipakai untuk tujuan lain.
2. Yang direkam: relawan berjalan lewat, berhenti, pergi, dan kembali di depan kamera kiosk
   sesuai arahan. Warna baju relawan akan diberi label oleh dua penilai.
3. Penyimpanan: foto dan video disimpan hanya di laptop pengembang, tidak diunggah ke
   repositori, layanan awan, atau API mana pun.
4. Identitas: relawan hanya dicatat sebagai kode anonim; nama tidak ditulis di manifest, nama
   file, atau hasil. Hasil yang dilaporkan berupa angka gabungan; tidak ada foto relawan di
   laporan tanpa persetujuan terpisah.
5. Penghapusan: foto dan video dihapus setelah skripsi selesai (setelah sidang dan revisi).
   Relawan boleh meminta datanya dihapus kapan saja sebelum itu.
6. Sukarela: relawan boleh berhenti kapan saja tanpa konsekuensi.

Baris manifest hanya boleh dibuat untuk frame atau klip yang semua orangnya sudah setuju;
manifest dengan satu baris tanpa persetujuan ditolak seluruhnya.

## Bagian 1: deteksi (`python -m mica.eval vision`)

- Kandidat: `yolo26n` dan `yolo26n-pose`, kotak kelas person, bobot ber-sha256 di
  `mica/vision/detector.py`, CPU, `vision.imgsz` dari config (640).
- Prediksi dijalankan sekali per model pada conf terkecil dalam daftar; metrik conf yang lebih
  tinggi dihitung dengan membuang kotak di bawah conf itu. Ini setara dengan menjalankan ulang
  pada conf itu karena NMS hanya menekan kotak oleh kotak berskor lebih tinggi.
- Metrik (gaya COCO, satu kelas):
  - pencocokan per frame: deteksi diurutkan menurut skor, setiap deteksi dipasangkan ke kotak
    label belum terpakai dengan IoU tertinggi bila IoU ≥ ambang;
  - AP = rata-rata presisi berinterpolasi (presisi maksimum pada recall ≥ r) di 101 titik
    recall 0; 0,01; ...; 1;
  - mAP@50 = AP pada IoU 0,5; mAP@50:95 = rata-rata AP pada IoU 0,50; 0,55; ...; 0,95;
  - IoU rata-rata = rata-rata IoU pasangan cocok pada ambang 0,5;
  - waktu per frame = waktu dinding satu panggilan predict (praproses, inferensi, pascaproses),
    satu panggilan pemanasan tidak dihitung; dilaporkan p50 dan p95 (interpolasi linear), FPS =
    1 / p50.
- Bootstrap: 1000 resample frame dengan pengembalian, **seed 20261018**
  (`numpy.random.default_rng`), percentile 2,5 dan 97,5. Resample yang sama dipakai untuk kedua
  model (berpasangan); CI dihitung untuk mAP@50:95 tiap model dan untuk selisihnya.
- Aturan model (pada conf bawaan 0,1): pemenang = mAP@50:95 tertinggi. Bila CI 95% bootstrap
  selisih mAP@50:95 (pemenang dikurangi kandidat lain) memuat 0, keduanya dianggap seri dan
  dipilih yang FPS-nya lebih tinggi (p50 waktu per frame lebih kecil).
- Faktor conf: `vision.conf` ∈ {0,1 (bawaan), 0,25, 0,5} pada model pemenang; dipakai nilai
  dengan mAP@50:95 tertinggi. Seri (nilai sama persis) -> 0,1, lalu nilai lebih kecil.
- Laporan tambahan (bukan aturan): mAP per kondisi `cahaya` dan `jarak`.

## Bagian 2: skenario sapaan (`python -m mica.eval vision-scenarios`)

- Model = pemenang bagian 1 dengan conf terpilih. Klip diputar lewat pipeline M-07 yang sama:
  `UltralyticsDetector` (ByteTrack, `vision.tracker`) lalu `PresenceTracker` dengan sinyal
  `shoulder_width` (carry-over yang sama). Pembaca video menggantikan kamera; waktu = indeks
  frame / fps klip. Deteksi berjalan pada `vision.fps_idle` (5) sepanjang klip, dengan aturan
  jadwal yang sama dengan `VisionLoop`; `vision.fps_busy` masih TBD (E-09) sehingga tidak
  dipakai di sini.
- `keypoint_torso.min_kp_conf` = 0,5 (nilai coba SDD bagian 12) tetap untuk semua kombinasi.
- Grid (81 kombinasi): `dwell_s` {1, 2, 3}, `leave_s` {2, 3, 5}, `min_shoulder_ratio`
  {0,18, 0,22, 0,26}, `regreet_cooldown_s` {0, 30, 60}.
- Sapaan dihitung dari `PersonArrived` dengan aturan M-09 (M-09 tidak dijalankan):
  `PersonArrived` menjadi sapaan bila waktunya ≥ waktu `PersonLeft` terakhir + cooldown.
- Pemetaan ke anotasi: sapaan milik kemunculan yang jendelanya [`masuk`, `pergi`] memuat waktu
  sapaan; bila lebih dari satu, kemunculan `berhenti` didahulukan, lalu yang `berhenti`-nya
  paling akhir sebelum sapaan (atau paling awal bila belum ada).
- Kemunculan `berhenti` "wajib disapa", kecuali kemunculan ulang orang yang sama dengan jeda
  (`berhenti` sekarang dikurangi `pergi` sebelumnya) ≤ cooldown: itu "tidak boleh disapa lagi".
- Metrik per kombinasi:
  - sapaan benar: kemunculan wajib disapa yang mendapat ≥ 1 sapaan;
  - sapaan terlewat: kemunculan wajib disapa tanpa sapaan;
  - sapaan salah: sapaan di kemunculan `lewat`, atau di luar semua jendela (dilaporkan juga
    terpisah);
  - sapaan ganda: sapaan kedua dan seterusnya di satu kemunculan wajib disapa, ditambah semua
    sapaan di kemunculan "tidak boleh disapa lagi";
  - waktu sapaan = waktu `PersonArrived` sapaan pertama dikurangi `berhenti`, untuk sapaan
    benar; dilaporkan p50 dan p95 (interpolasi linear). Audio sapaan diukur di E-09.
- Aturan pemilihan (mekanis, `verdict.md`):
  1. Lolos bila p95 waktu sapaan + 1 detik cadangan TTS ≤ 3 detik (N-06) dan sapaan ganda = 0
     (F-04). Cadangan 1 detik diambil dari anggaran "cek fakta dan TTS kalimat pertama" SDD
     3.3. Kombinasi tanpa satu pun sapaan benar tidak lolos.
  2. Dari yang lolos, pilih jumlah (terlewat + salah) terkecil.
  3. Seri -> `dwell_s` lebih besar, lalu `regreet_cooldown_s` lebih besar (lebih konservatif,
     sesuai tujuan "tidak sok tau"), lalu `leave_s` lebih besar, lalu `min_shoulder_ratio`
     lebih besar.
  4. Tidak ada yang lolos -> tidak ada pemenang; dilaporkan apa adanya.
- Bila pemenang bagian 1 `yolo26n` (tanpa keypoint), sinyal bahu tidak tersedia. Grid
  `min_box_height_ratio` untuk sinyal `box_height` belum ditetapkan; harus ditambahkan lewat
  amandemen tertulis di dokumen ini sebelum klip skenario dibuka. Perintah menolak model tanpa
  `-pose`.

## Perintah

Semua perintah hanya jalan di mode dev.

```
python -m mica.eval vision --config config/dev.yaml --dataset data/eval/vision/<nama> \
    --models yolo26n,yolo26n-pose --conf 0.1,0.25,0.5 --out results/E-07/
python -m mica.eval vision-scenarios --config config/dev.yaml \
    --dataset data/eval/vision_scenarios/<nama> --model <pemenang> --conf <terpilih> \
    --grid default --out results/E-07/
```

Hasil: `summary.csv`, `per_frame.csv` atau `grid.csv`, `verdict.md`, dan `run.json` (sha256
model, data, dan manifest; versi paket; CPU; AC/baterai; commit). Run dari commit bersih
(`git_dirty` false) dengan daya AC untuk angka skripsi.
