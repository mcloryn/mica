# E-09: latensi, kalibrasi CPU, dan RAM sesi panjang (pra-registrasi)

Ditetapkan 18 Oktober 2026, sebelum data E-09 dikumpulkan. Aturan di bawah tidak diubah setelah
data ada; penyimpangan wajib ditulis di hasil dan diungkap di Bab 3. Angka yang belum
disepakati ditulis TBD.

## Tujuan

1. Memverifikasi anggaran latensi SDD 3.3, N-05 (total ≤ 10 detik), K-3 (respons pertama
   ≤ 3 detik), dan N-06 (sapaan ≤ 3 detik) dengan UI web (ADR-19, keputusan pemilik proyek
   17 Okt 2026) di laptop kiosk atau laptop yang mirip.
2. Menetapkan `vision.fps_busy`, `vision.threads`, dan `audio.stt.threads`.
3. Memverifikasi RAM UI web pada sesi panjang.

## Kondisi

- Semua proses asli: kamera (vision), suara (VAD, STT, TTS), RAG konfigurasi C2, dan UI web
  (Flask + Edge kiosk). Tanpa `--fake-workers` atau `--fake-pipeline`.
- Daya AC. Power plan dicatat di run.json.
- Run dari commit bersih (`git_dirty` false). Run dari pohon kotor hanya untuk percobaan, tidak
  untuk angka skripsi.
- Perekam sumber daya aktif: `--record-resources <folder> --e09` (interval bawaan 5 detik,
  nilai coba).
- Jumlah pertanyaan dan pengunjung per kombinasi kalibrasi: TBD, disepakati sebelum run.

## Definisi waktu (dari log 6.2, `logs/turns-*.jsonl` dan `logs/events-*.jsonl`)

Semua waktu dalam detik dan dibaca dari `timings` setiap giliran.

| Kunci | Arti |
| --- | --- |
| `vad` | Deteksi akhir ucapan: diam di ujung ucapan sampai VAD menyatakan ucapan selesai |
| `stt` | Lama transkripsi ucapan |
| `retrieval` | Retrieval (di pipeline) |
| `gate` | Gerbang (kunci tambahan pipeline) |
| `llm` | LLM sampai jawaban lengkap |
| `check` | Cek fakta |
| `tts_first_audio` | `Speak` jawaban diterima proses suara sampai audio pertama diputar |
| `total` | Akhir ucapan (suara) atau kirim teks (ketik) sampai audio jawaban pertama mulai; bila jawaban tidak bersuara (speaker tidak ada atau diputus), sampai jawaban diterima controller |
| `first_response` | Respons pertama K-3: akhir ucapan sampai UI web mengirim ack untuk tampilan transkripsi + status "berpikir" |

- Untuk input ketik, kunci suara (`vad`, `stt`, `first_response`) bernilai null, bukan 0.
  Input ketik tidak masuk statistik tahap suara.
- "Akhir ucapan" = saat VAD menyatakan ucapan selesai dikurangi `vad`, yaitu potongan
  bicara terakhir.
- Sapaan (N-06) = `latency_s` pada event `greeted`: dari target memenuhi `dwell_s`
  (`PersonArrived`) sampai audio sapaan mulai diputar.

## Aturan lulus (diterapkan mekanis oleh `python -m mica.eval latency`)

Persentil memakai interpolasi linear (`numpy.percentile` bawaan), sama dengan eval lain di
repo (`mica.eval.metrics.percentile`). Nilai null diabaikan dan jumlahnya dilaporkan.

| Ukuran | Syarat (p95) | Sumber |
| --- | --- | --- |
| `vad` | ≤ 0,5 detik | SDD 3.3 |
| `stt` | ≤ 1,5 detik | SDD 3.3 |
| `retrieval` + `gate` | ≤ 0,5 detik | SDD 3.3 "Retrieval dan gerbang" |
| `llm` | ≤ 4 detik | SDD 3.3 |
| `check` + `tts_first_audio` | ≤ 1 detik | SDD 3.3 "Cek fakta dan TTS kalimat pertama" |
| `total` | ≤ 10 detik | N-05 |
| `first_response` | ≤ 3 detik | K-3 |
| sapaan (`latency_s` `greeted`) | ≤ 3 detik | N-06 |

- Tahap suara (`vad`, `stt`) hanya dihitung dari input suara. Tahap lain, `total`, dihitung
  per jenis input (suara dan ketik); syarat N-05 berlaku untuk suara.
- LULUS bila p95 `total` (suara), `first_response`, dan sapaan memenuhi syarat. Tahap yang
  melewati anggaran 3.3 sementara total dan K-3 aman dilaporkan sebagai **"lewat anggaran
  tahap"**, bukan gagal (sudah terjadi pada STT di laptop dev, SDD 2.4).
- GAGAL bila salah satu dari `total` (suara), `first_response`, atau sapaan melewati syarat.
- Ukuran tanpa data (n = 0) dilaporkan "tidak ada data", tidak lulus dan tidak gagal.

## Kalibrasi (grid ditetapkan sekarang)

- `vision.fps_busy` ∈ {1, 2, 5}
- `vision.threads` ∈ {1, 2}
- `audio.stt.threads` ∈ {2, 4}

Pilih kombinasi yang memenuhi semua aturan lulus dengan p95 `total` (suara) terendah. Bila seri,
yaitu selisih p95 total lebih kecil dari rentang antar-ulangan (maksimum dikurangi minimum p95
total per ulangan kombinasi terbaik), pilih kombinasi yang CPU rata-ratanya lebih rendah (rata-rata
CPU seluruh kelompok proses dari perekam sumber daya). Bila tidak ada kombinasi yang lulus,
optimasi dulu (ADR-19, keputusan pemilik proyek); PySide6 adalah jalan keluar terakhir.

## Sesi panjang (RAM)

- Kiosk dijalankan satu hari uji penuh dengan konfigurasi hasil kalibrasi. Jam mulai dan
  selesai dicatat.
- Perekam sumber daya mencatat RAM USS dan CPU per kelompok proses (utama, vision, suara, Edge
  dan turunannya) setiap 5 detik (nilai coba).
- Dilaporkan per kelompok: nilai awal, akhir, dan kemiringan (MB per jam, regresi kuadrat
  terkecil). Tidak ada ambang angka. Bila RAM terus naik, penyebabnya dicari dan dilaporkan.

## Amandemen 1 (18 Okt 2026, sebelum data E-09)

Ditetapkan sebelum data E-09 dikumpulkan (Langkah 37, UI kiosk baru dengan pratinjau kamera).

- E-09 diukur dengan `ui.camera_preview = public` (nilai kiosk.yaml), karena kiosk memakai
  pratinjau public. Nilai coba desain `ui.preview_pixel_block` 16 dan `ui.preview_fps` 5
  dicatat di run.json lewat config. Kombinasi kalibrasi dan aturan lulus tidak berubah.
- Biaya pratinjau yang diukur di laptop dev dengan sumber gambar palsu (Langkah 37,
  results/ADR-19/ui-l37-*) hanya laporan; keputusan apakah pratinjau public tetap dipakai
  diambil dari aturan lulus E-09 di atas. Bila E-09 gagal karena beban pratinjau, pilihan
  `ui.preview_fps` lebih kecil atau `ui.camera_preview = off` dicatat sebagai keputusan
  desain pemilik proyek, bukan hasil eksperimen.

## Amandemen 2 (18 Okt 2026, sebelum data E-09)

Ditetapkan sebelum data E-09 dikumpulkan. Alasannya keputusan desain pengguna 18 Okt 2026:
input suara menjadi push-to-talk (`audio.input_mode: push_to_talk`, bawaan dev dan kiosk;
Langkah 42). Pengunjung menahan tombol Bicara selama berbicara lalu melepasnya. VAD tidak lagi
menentukan akhir ucapan.

- Untuk input suara push-to-talk, awal waktu `total` dan `first_response` = saat tombol dilepas
  (`Utterance.ended_t`, monotonic proses suara), bukan akhir ucapan menurut VAD. Definisi
  "Akhir ucapan" di bagian Definisi waktu diganti dengan "saat tombol dilepas" untuk mode ini.
- `vad` dicatat sebagai lama cek VAD setelah tombol dilepas. Cek itu memastikan ada ucapan dan
  memangkas hening di awal/akhir rekaman, dan dihitung dari tombol dilepas sampai audio siap
  dikirim ke STT. Anggaran deteksi akhir ucapan 0,5 detik di SDD 3.3 tidak berlaku untuk
  push-to-talk; nilai `vad` tetap dilaporkan apa adanya.
- Rekaman yang mencapai `audio.max_utterance_s` sebelum tombol dilepas dikirim otomatis; awal
  waktunya saat batas tercapai.
- Rekaman tanpa ucapan (tombol dilepas tanpa bicara) tidak memanggil STT. Giliran seperti itu
  tidak menghasilkan baris giliran dan tidak masuk statistik.
- Mode lama `audio.input_mode: vad` tetap tersedia untuk perbandingan, dengan definisi waktu
  semula. Aturan lulus, grid kalibrasi, dan sesi panjang tidak berubah.
